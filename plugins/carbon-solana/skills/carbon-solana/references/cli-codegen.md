# `carbon-cli` — code generation from IDLs

`@sevenlabs-hq/carbon-cli` (npm) generates Carbon decoder crates and project skeletons from Anchor or Codama IDLs. Use it instead of writing decoder boilerplate by hand whenever you have an IDL or just a program address.

## Install

```sh
npm install -g @sevenlabs-hq/carbon-cli
# or run on demand:
npx @sevenlabs-hq/carbon-cli parse [...]
```

## `parse` — generate just the decoder

```sh
carbon-cli parse [OPTIONS]
```

| Option | Default | Notes |
|---|---|---|
| `-i, --idl <fileOrAddress>` | (required) | Path to a JSON IDL **or** a Solana program address. With an address, `--url` is required. |
| `-o, --out-dir <dir>` | (required) | Output directory. Cleared first unless `--no-clean` is set. |
| `-c, --as-crate` | `false` | Emit a full `Cargo.toml` + crate layout. Without this, just produces the source tree (good for embedding into an existing crate). |
| `-s, --standard <anchor\|codama>` | `anchor` | IDL flavor. Codama is needed for newer programs that ship Codama IDLs (e.g. Pumpfun). |
| `--event-hints <csv>` | — | Codama only. Defined-type names (e.g. `TradeEvent,CreateEvent`) to generate as CPI events. The CLI doesn't auto-detect events from a Codama IDL — you must hint. |
| `-u, --url <rpcUrl>` | — | RPC URL when `--idl` is a program address. Accepts `mainnet-beta`, `devnet`, or a full URL. The CLI fetches the on-chain PDA IDL. |
| `--no-clean` | `false` | Don't delete output directory before rendering. Use to merge with hand-written code. |

### Examples

```sh
# Anchor IDL file -> embedded source
carbon-cli parse --idl my_program.json --out-dir ./src/decoders

# Anchor IDL -> standalone crate
carbon-cli parse --idl my_program.json --out-dir ./crates/my-decoder --as-crate

# Program address -> fetch IDL from chain (Anchor)
carbon-cli parse --idl LBUZKhRxPF3XUpBCjp4YzTKgLccjZhTSDM9YuVaPwxo --url mainnet-beta --out-dir ./src/decoders

# Codama IDL with explicit event types
carbon-cli parse --idl pumpfun_codama.json --out-dir ./src/decoders --standard codama --event-hints "TradeEvent,CreateEvent,CompleteEvent"
```

## `scaffold` — generate a full indexer project

```sh
carbon-cli scaffold [OPTIONS]
```

Wires up a Cargo workspace, the chosen datasource, the chosen metrics sink, optional Postgres/GraphQL plumbing, and a stub processor.

| Option | Default | Notes |
|---|---|---|
| `-n, --name <string>` | (required) | Project name (Cargo + npm safe). |
| `-o, --out-dir <dir>` | (required) | Project root. |
| `-d, --decoder <name>` | auto | Decoder name; auto-detected from IDL when possible. |
| `--idl <fileOrAddress>` | — | Same as `parse --idl`. |
| `--idl-standard <anchor\|codama>` | `anchor` | Same as `parse --standard`. |
| `--idl-url <rpcUrl>` | — | Required if `--idl` is an address. |
| `--event-hints <csv>` | — | Same as `parse --event-hints`. |
| `-s, --data-source <name>` | (required) | One of: `rpc-block-subscribe`, `rpc-program-subscribe`, `rpc-transaction-crawler`, `helius-laserstream`, `yellowstone-grpc`, `jito-shredstream-grpc`. |
| `-m, --metrics <log\|prometheus>` | `log` | `log` = `carbon-log-metrics`; `prometheus` = `carbon-prometheus-metrics`. |
| `--with-postgres <bool>` | `true` | Adds `sqlx` + Carbon's postgres helpers and a starter migration directory. |
| `--with-graphql <bool>` | `true` | Wires Carbon's GraphQL feature flag and a starter resolver. |
| `--with-serde <bool>` | `false` | Enables `serde` derives on the generated decoder. |
| `--force` | `false` | Overwrite output directory if it exists. |

### Examples

```sh
# Yellowstone-based indexer for a known IDL file
carbon-cli scaffold --name pump-indexer --out-dir . \
    --idl ./pumpfun.json --idl-standard codama \
    --event-hints "TradeEvent,CreateEvent,CompleteEvent" \
    --data-source yellowstone-grpc --metrics prometheus \
    --with-postgres true --with-graphql false

# Block-subscribe indexer (no special infra) from a program address
carbon-cli scaffold --name simple-indexer --out-dir . \
    --idl LBUZKhRxPF3XUpBCjp4YzTKgLccjZhTSDM9YuVaPwxo --idl-url mainnet-beta \
    --data-source rpc-block-subscribe
```

## Interactive mode

Both commands prompt when invoked without required options:

```sh
carbon-cli parse
carbon-cli scaffold
```

## What the generator emits

`parse` produces:
```
out-dir/
  src/
    lib.rs                # PROGRAM_ID const + decoder unit struct + module decls
    accounts/             # one file per IDL account + mod.rs
    instructions/         # one file per IDL instruction + mod.rs (with the umbrella enum + InstructionDecoder impl)
    types/                # IDL `defined types` + a *_event.rs per --event-hint type (Codama only)
    events/               # only when --event-hints given (Codama only)
  Cargo.toml              # only if --as-crate
```

The generated code includes a `// This code was AUTOGENERATED using the Codama library.` header on each file. It is safe to regenerate over hand-edits if you `--no-clean`-merge or git-rebase your changes.

## When the IDL doesn't match real on-chain shape

Some Solana programs change their wire format faster than they update their IDL (especially Anchor programs that rely on private discriminators). Symptoms: `decode_instruction` returns `None` for transactions you can see hitting the program. Fixes:
- Regenerate from a fresher IDL.
- Hand-edit the generated `instructions/<name>.rs` to match — most fixes are adjusting the `match accounts.len()` arms or the field types.
- Open a PR against `sevenlabs-hq/carbon`. The decoder crates in this repo are the source of truth for popular protocols (and supersede whatever the CLI generates).

## Don't regenerate official decoders

The 60+ decoders shipped under `decoders/` in the Carbon repo have hand-tuned account variants and bug fixes that the CLI alone won't produce. **Use those crates from crates.io as-is** rather than regenerating from the public IDL — see `references/protocols/_index.md` for the full list.
