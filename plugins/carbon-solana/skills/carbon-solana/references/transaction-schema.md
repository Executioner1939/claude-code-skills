# Transaction schema matching

`.transaction::<T, U>(schema, processor)` runs the processor only when the **whole** transaction matches a structural pattern. Use it when:
- A meaningful event spans multiple instructions (initialize then deposit, swap then settle).
- You want to extract several instructions and consume them together.
- You need to handle inner-instruction patterns hierarchically.

For single-instruction handling, use `.instruction(...)` instead — it's simpler and faster.

## Building a schema

`carbon_core::schema::TransactionSchema<T>` is a list of `SchemaNode` values:

```rust
pub enum SchemaNode<T: InstructionDecoderCollection> {
    Instruction(InstructionSchemaNode<T>),
    Any,                                                 // wildcard, matches any instruction
}

pub struct InstructionSchemaNode<T: InstructionDecoderCollection> {
    pub ix_type: T::InstructionType,                     // the variant (data-free) tag, e.g. RaydiumAmmV4InstructionType::SwapBaseIn
    pub name: String,                                    // your label; appears in match output
    pub inner_instructions: Vec<SchemaNode<T>>,          // recursive
}
```

Use the `schema!` macro to write schemas inline:

```rust
use carbon_core::schema;

let s = schema![
    any,
    [
        AllInstructionTypes::Raydium(RaydiumAmmV4InstructionType::Initialize2),
        "init",
        [ /* nested matchers */ ]
    ],
    any,
];
```

Three forms inside the macro:
1. `any` — `SchemaNode::Any`. Skips zero or more instructions.
2. `[ix_type, name]` — `SchemaNode::Instruction { ix_type, name, inner_instructions: vec![] }`.
3. `[ix_type, name, [...]]` — same but with nested matchers for the instruction's inner CPIs.

## InstructionDecoderCollection

For multi-program schemas you need a single enum that wraps every program's instruction enum. `carbon-proc-macros` provides the `InstructionDecoderCollection` derive (and a companion `InstructionType`):

```rust
use carbon_core::collection::InstructionDecoderCollection;

#[derive(InstructionDecoderCollection, /* ... */)]
pub enum AllInstructions {
    Raydium(RaydiumAmmV4Instruction),
    Pumpfun(PumpfunInstruction),
}

#[derive(/* auto-derived InstructionType variant */)]
pub enum AllInstructionTypes {
    Raydium(RaydiumAmmV4InstructionType),     // data-free version of Instruction enum
    Pumpfun(PumpfunInstructionType),
}
```

Each per-program decoder already provides a `<Name>InstructionType` enum (data-free shadow of `<Name>Instruction`) generated by `#[derive(carbon_core::InstructionType)]` in its `instructions/mod.rs`.

## Matching and extraction

When the pipeline parses a transaction, the registered transaction pipe:
1. Decodes every instruction into `Vec<ParsedInstruction<T>>` (built into a tree by stack height).
2. Calls `schema.match_schema::<U>(parsed)` if a `U` was registered, OR `schema.match_nodes(parsed)` for the raw map.

`match_nodes` returns `Option<HashMap<String, (T, Vec<AccountMeta>)>>` keyed by the names you gave each `Instruction` node. `match_schema::<U>` first runs `match_nodes`, JSON-roundtrips it, and deserializes into your custom `U`.

Define `U` with field names that match the schema node names:

```rust
#[derive(Deserialize)]
struct InitFlow {
    init: (RaydiumAmmV4Instruction, Vec<AccountMeta>),
    first_swap: (RaydiumAmmV4Instruction, Vec<AccountMeta>),
}

let schema: TransactionSchema<RaydiumAmmV4Instruction> = schema![
    [RaydiumAmmV4InstructionType::Initialize2, "init"],
    any,
    [RaydiumAmmV4InstructionType::SwapBaseIn, "first_swap"],
];

Pipeline::builder()
    .datasource(...)
    .transaction::<RaydiumAmmV4Instruction, InitFlow>(schema, MyProcessor)
    .build()?.run().await
```

Your processor receives:
```rust
type InputType = (
    Arc<TransactionMetadata>,
    Vec<(InstructionMetadata, DecodedInstruction<T>)>,
    Option<U>,             // Some(InitFlow { ... }) when schema matched, None otherwise
);
```

When the `Option<U>` is `None`, the schema didn't match but the processor still fires (with the full instruction list). When it's `Some(u)`, you can use `u` directly. If you only want the matched cases, early-return on `None`.

## Matching semantics

- Matching is **sequential** at each tree level. The schema's nodes are consumed in order against the instruction list at the same level.
- `Any` is greedy — it skips instructions until the next `Instruction` node finds a match. Use it as a "don't care" between fixed anchors.
- A non-`Any` `Instruction` node must match the next non-skipped instruction's `ix_type` exactly, otherwise the entire match fails (returns `None`).
- For inner instructions, the matcher recurses with the same rules; the inner schema must match against `current_instruction.inner_instructions`.

## When schema matching falls short

- If you need full pattern flexibility (regex-style, optional matches, alternations beyond `Any`), do the matching yourself in an instruction processor with an in-memory state machine keyed by `signature`.
- For multi-transaction patterns (transactions across slots), aggregate state in the processor (`Arc<RwLock<HashMap<...>>>`).

## Schema for cross-program patterns

```rust
let schema = schema![
    any,
    [
        AllInstructionTypes::Token(TokenProgramInstructionType::Transfer),
        "deposit_transfer"
    ],
    [
        AllInstructionTypes::Raydium(RaydiumAmmV4InstructionType::SwapBaseIn),
        "swap"
    ],
    any,
];
```

A successful match returns:
```rust
{
    "deposit_transfer": (Token(Transfer { amount, .. }), [accounts...]),
    "swap":             (Raydium(SwapBaseIn { amount_in, .. }), [accounts...]),
}
```
