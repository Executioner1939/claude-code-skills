# Decoder anatomy

Every protocol decoder in `decoders/<name>-decoder` follows the same shape so that swapping in a new program is trivial.

## Crate exports

```rust
pub struct <Name>Decoder;                                 // unit struct, used as the value passed to .instruction(...)/.account(...)
pub const PROGRAM_ID: solana_pubkey::Pubkey;              // base58 string compiled in via Pubkey::from_str_const
pub mod accounts;                                         // pub enum <Name>Account + AccountDecoder impl
pub mod instructions;                                     // pub enum <Name>Instruction + InstructionDecoder impl
pub mod types;                                            // shared types; some events live here as *_event.rs
pub mod events;                                           // ONLY on Codama-generated decoders (anchor-style CPI events)
pub mod graphql;                                          // optional, behind `feature = "graphql"`
pub mod postgres;                                         // optional, behind `feature = "postgres"`
```

## Instructions module

`instructions/mod.rs` declares the umbrella enum and implements `InstructionDecoder`:

```rust
#[derive(carbon_core::InstructionType, Serialize, Deserialize, ...)]
pub enum <Name>Instruction {
    Initialize(initialize::Initialize),
    SwapBaseIn(swap_base_in::SwapBaseIn),
    // ... one variant per file
}

impl carbon_core::instruction::InstructionDecoder<'_> for <Name>Decoder {
    type InstructionType = <Name>Instruction;
    fn decode_instruction(&self, ix: &solana_instruction::Instruction)
        -> Option<carbon_core::instruction::DecodedInstruction<Self::InstructionType>>
    {
        if !ix.program_id.eq(&PROGRAM_ID) { return None; }
        carbon_core::try_decode_instructions!(ix,
            <Name>Instruction::Initialize  => initialize::Initialize,
            <Name>Instruction::SwapBaseIn  => swap_base_in::SwapBaseIn,
            // ...
        )
    }
}
```

The `try_decode_instructions!` macro is a fall-through: it tries each variant's `CarbonDeserialize::deserialize` until one succeeds, returning a `DecodedInstruction { program_id, accounts, data }`.

## A single instruction file

Two patterns. Both produce the same `arrange_accounts` interface; pick the right reading strategy when scanning unfamiliar files.

### Pattern A — discriminator attribute, length-matched accounts

```rust
use carbon_core::{borsh, CarbonDeserialize};

#[derive(CarbonDeserialize, Serialize, ...)]
#[carbon(discriminator = "0x09")]      // single byte, prepended to the borsh-encoded args
pub struct SwapBaseIn {
    pub amount_in: u64,
    pub minimum_amount_out: u64,
}

#[derive(Debug)]
pub struct SwapBaseInInstructionAccounts {
    pub token_program: Pubkey,
    pub amm: Pubkey,
    pub amm_authority: Pubkey,
    pub amm_open_orders: Pubkey,
    pub amm_target_orders: Option<Pubkey>,           // <-- optional => present only in some variants
    pub pool_coin_token_account: Pubkey,
    /* ... */
}

impl carbon_core::deserialize::ArrangeAccounts for SwapBaseIn {
    type ArrangedAccounts = SwapBaseInInstructionAccounts;
    fn arrange_accounts(accounts: &[AccountMeta]) -> Option<Self::ArrangedAccounts> {
        match accounts.len() {
            17 => { /* destructure WITHOUT amm_target_orders, set it to None */ }
            18 => { /* destructure WITH amm_target_orders, set it to Some(...) */ }
            _  => None,
        }
    }
}
```

### Pattern B — anchor 8-byte discriminator, sequential `next_account`

Generated by `carbon-cli` from Anchor/Codama IDLs:

```rust
use carbon_core::account_utils::next_account;
use carbon_core::deserialize::ArrangeAccounts;

#[derive(borsh::BorshSerialize, borsh::BorshDeserialize, ...)]
pub struct Buy {
    pub amount: u64,
    pub max_sol_cost: u64,
    pub track_volume: OptionBool,
}

pub struct BuyInstructionAccounts {
    pub global: Pubkey,
    pub fee_recipient: Pubkey,
    /* ... */
    pub remaining: Vec<AccountMeta>,                  // <-- optional trailing accounts
}

impl Buy {
    pub fn decode(data: &[u8]) -> Option<Self> {
        if data.len() < 8 { return None; }
        if &data[0..8] != [102, 6, 61, 18, 1, 218, 235, 234] { return None; }
        borsh::BorshDeserialize::deserialize(&mut &data[8..]).ok()
    }
}

impl ArrangeAccounts for Buy {
    type ArrangedAccounts = BuyInstructionAccounts;
    fn arrange_accounts(accounts: &[AccountMeta]) -> Option<Self::ArrangedAccounts> {
        let mut iter = accounts.iter();
        let global         = next_account(&mut iter)?;
        let fee_recipient  = next_account(&mut iter)?;
        /* ... */
        let remaining      = iter.as_slice().to_vec();
        Some(BuyInstructionAccounts { global, fee_recipient, /*...*/ remaining })
    }
}
```

## Discriminator styles

| Style | Where you'll see it | Example | How to read it |
|---|---|---|---|
| **Single byte** | Native (Raydium AMM v4, OpenBook, SPL Token) | `0x09` | First byte of instruction data is the variant tag. |
| **Anchor 8-byte** | Anchor & Codama programs (Pumpfun, Raydium CPMM, Drift, Kamino, Jupiter, etc.) | `[102, 6, 61, 18, 1, 218, 235, 234]` | First 8 bytes; computed as `sha256("global:<ix_name>")[..8]`. |
| **u32 LE** | System program | `0x02 0x00 0x00 0x00` | First 4 bytes little-endian = variant tag. |
| **Mixed** | Some programs | varies | The protocol page tags the file with the actual byte string. |

`extract_discriminator(length, data)` in `carbon_core::deserialize` slices off the prefix and returns `(discriminator, rest)`.

## Accounts module

`accounts/mod.rs` declares the umbrella enum and implements `AccountDecoder`:

```rust
pub enum <Name>Account {
    AmmInfo(amm_info::AmmInfo),
    Fees(fees::Fees),
    /* ... */
}

impl AccountDecoder<'_> for <Name>Decoder {
    type AccountType = <Name>Account;
    fn decode_account(&self, account: &solana_account::Account)
        -> Option<DecodedAccount<Self::AccountType>>
    {
        if !account.owner.eq(&PROGRAM_ID) { return None; }
        match account.data.len() {                    // size-based dispatch (most native programs)
            amm_info::AMM_INFO_SIZE => /* deserialize AmmInfo */,
            fees::FEES_SIZE         => /* deserialize Fees */,
            _ => None,
        }
    }
}
```

For Anchor accounts, the dispatch is by 8-byte discriminator instead of `data.len()`. Either way the `decode_account` returns `DecodedAccount { lamports, data, owner, executable, rent_epoch }`.

Each `accounts/<name>.rs` declares the struct + `pub const <NAME>_SIZE: usize = core::mem::size_of::<...>()` for native-sized accounts.

## Events module (when present)

Codama-generated decoders that ingest IDLs with `--event-hints` produce one file per event in `events/`:

```rust
#[derive(borsh::BorshSerialize, borsh::BorshDeserialize, ...)]
pub struct TradeEventEvent {
    pub mint: Pubkey,
    pub sol_amount: u64,
    pub token_amount: u64,
    /* ... */
}

impl TradeEventEvent {
    pub fn decode(data: &[u8]) -> Option<Self> {
        if data.len() < 8 { return None; }
        if &data[0..8] != [189, 219, 127, 211, 78, 230, 97, 238] { return None; }
        borsh::BorshDeserialize::deserialize(&mut &data[8..]).ok()
    }
}
```

The discriminator is the standard Anchor event prefix: `sha256("event:<EventName>")[..8]`.

For programs without an `events/` folder but that still emit CPI events (Raydium CPMM is the canonical case), the event types live alongside other shared types in `types/<name>_event.rs`. Either way: pass the type to `InstructionMetadata::decode_log_events::<T>()` to extract instances from the surrounding instruction's logs.

## Types module

`types/` holds shared structs referenced by accounts and instructions: pool configs, math state, enum tags. Skim the protocol page's "Shared types" section to see which apply.

## CarbonDeserialize trait (manual implementation)

If you write your own decoder by hand instead of generating, derive `CarbonDeserialize`:

```rust
use carbon_core::{borsh, CarbonDeserialize};

#[derive(CarbonDeserialize, Debug, Clone, BorshDeserialize, BorshSerialize, PartialEq)]
#[carbon(discriminator = "0x42")]
pub struct MyIx {
    pub amount: u64,
}

// equivalent to:
impl CarbonDeserialize for MyIx {
    const DISCRIMINATOR: &'static [u8] = &[0x42];
    fn deserialize(data: &[u8]) -> Option<Self> {
        let (disc, rest) = extract_discriminator(1, data)?;
        if disc != Self::DISCRIMINATOR { return None; }
        borsh::BorshDeserialize::deserialize(&mut &rest[..]).ok()
    }
}
```

The `#[carbon(discriminator = "...")]` attribute accepts:
- `"0x09"` — a single byte (interprets the hex as 1 byte).
- `"0x09,0xab"` — multiple bytes.
- A bare 8-byte array like `"[102, 6, 61, 18, 1, 218, 235, 234]"` — full anchor discriminators (rarely written by hand; usually generated).

## Putting it together

1. Pick the right decoder for your program (find its slug in `references/protocols/_index.md`).
2. Add the crate to `Cargo.toml`: `carbon-<slug>-decoder = "<version>"`.
3. Use `<Name>Decoder` in `.instruction(...)` and/or `.account(...)`.
4. Match on `<Name>Instruction::<Variant>(args)` in your processor's `process` fn.
5. Call `<Variant>::arrange_accounts(&ix.accounts)` to get named pubkeys.
6. For Anchor-style programs, also call `instruction_metadata.decode_log_events::<MyEvent>()` to capture CPI events emitted by that instruction.
